# Implementation Plan: OpenAPI and Swagger UI Documentation

**Branch**: `002-openapi-swagger` | **Date**: 2026-10-28 | **Spec**: [spec.md](./spec.md)

**Input**: Feature specification from `/specs/002-openapi-swagger/spec.md`

---

## Summary

Integrate SpringDoc OpenAPI 2.x (`springdoc-openapi-starter-webmvc-ui:2.6.0`) into the Spring Boot 3.3.5 service to provide automated OpenAPI 3.0 specification generation (`/v3/api-docs`) and an interactive Swagger UI (`/swagger-ui.html`). Configure Spring Security to permit public access to documentation routes while securing business endpoints with OAuth 2.0 Bearer JWT authentication, exposing the `bearerAuth` security scheme directly in Swagger UI for interactive execution.

---

## Technical Context

**Language/Version**: Java 21 (LTS)  
**Primary Dependencies**:
- Spring Boot 3.3.5
- `org.springdoc:springdoc-openapi-starter-webmvc-ui:2.6.0`
- Spring Security 6.x (Resource Server OAuth 2.0 JWT)
- Spring MVC Web

**Storage**: PostgreSQL (no changes to database schema or migrations required)  
**Testing**:
- ArchUnit 1.3.0 (verifying no OpenAPI annotation leak into domain/application layers)
- MockMvc (`@WebMvcTest` and `@SpringBootTest`) verifying public access to `/v3/api-docs` and `/swagger-ui/**`
- JUnit 5 / AssertJ

**Target Platform**: Linux container (Docker) & local development  
**Project Type**: Spring Boot Web REST microservice  
**Performance Goals**: Swagger UI page load < 1s; OpenAPI JSON spec response < 100ms  
**Constraints**: Zero impact on existing domain/application hexagonal layer boundaries; 100% backward compatibility with all existing 23 tests  
**Scale/Scope**: 1 controller (`ActivationController`), 3 endpoints, 4 DTOs/records
